01 / The question

Card fraud costs billions every year and fraud patterns shift faster than hand-written rules. Using the IEEE-CIS dataset (transactions joined with device and identity records), the goal was to score every transaction for fraud risk. Only about 1 in 29 transactions is fraud, many identity fields are more than 90% missing, and card and device IDs have hundreds of distinct values, so a model that always says "not fraud" already reaches 96.5% accuracy. Accuracy is useless here; the project is judged on ROC-AUC and PR-AUC.

02 / Process

How I built it

  1. 01

    Merge and order by time

    Joined the transaction and identity tables and sorted by transaction time. Split chronologically 80 / 10 / 10 into train, validation and a final holdout, so the model never sees the future.

  2. 02

    Leakage-free preprocessing

    Every statistic is learned on the training slice only: train-median imputation with a missing flag, frequency encoding for high-cardinality categories (unseen values map to the rarest frequency), a zero-variance filter, sin/cos encoding of hour and weekday, log-transformed amounts. Everything is saved to one preprocessing file so all models see identical rows.

  3. 03

    XGBoost

    Compared three configurations (balanced, deeper, regularised) by validation AUC with early stopping and class re-weighting (scale_pos_weight 27.5). The regularised model won: validation AUC 0.9217 with 616 trees.

  4. 04

    LightGBM

    Weighted loss where a fraud mistake counts 27.46× a normal one; compared 31 vs 63 leaves. The 63-leaf model won with 954 boosting rounds.

  5. 05

    Stacked ensemble

    Added 10 train-only behavioural aggregates, let XGBoost, LightGBM and CatBoost each pick their own features with forward-chaining time folds (429 features in the union), tuned coarse-to-fine on PR-AUC, then stacked the three probabilities with a logistic meta-model.

  6. 06

    Calibrate and set the threshold

    Chose Platt scaling over isotonic by Brier score on a held-out split and picked the decision threshold on validation data only, then scored the holdout exactly once.
