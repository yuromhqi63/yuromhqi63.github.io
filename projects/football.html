01 / The question

A football association needs to store clubs, players, captains and stakeholders. The rules sound simple, but they hide tricky constraints: every club has exactly one captain, the captain must play for that same club, and a stakeholder is only identified together with the club they own part of. The aim was a design where the database itself rejects invalid data.

02 / Process

How I built it

  1. 01

    State the assumptions

    Wrote down 7 assumptions before modelling: current state only, every player in exactly one club, exactly one captain per club, non-negative salary and asset, ownership between 0 and 100%.

  2. 02

    Draw the ER diagram

    Player, Club and the weak entity Stakeholder; relationships Plays_for (1,1)–(1,n), Captains (0,1)–(1,1) and the identifying relationship Has, with (min,max) cardinalities.

  3. 03

    Map to relations

    Plays_for folds into Player as club_name; Captains folds into Club as a NOT NULL captain_pid; Stakeholder gets the key (club_name, name) with ON DELETE CASCADE.

  4. 04

    Enforce "the captain plays for this club"

    A composite foreign key Club(captain_pid, name) → Player(pid, club_name), made possible by declaring (pid, club_name) UNIQUE in Player.

  5. 05

    Break the chicken-and-egg loop

    A new club needs a captain and a new player needs a club, so both foreign keys are DEFERRABLE INITIALLY DEFERRED and checked at COMMIT.

Key SQL

CREATE TABLE Player (
    pid        INTEGER,
    dob        DATE          NOT NULL,
    position   VARCHAR(20)   NOT NULL,
    salary     NUMERIC(12,2) NOT NULL CHECK (salary >= 0),
    club_name  VARCHAR(50)   NOT NULL,
    PRIMARY KEY (pid),
    UNIQUE (pid, club_name),            -- referenced by the captain FK
    FOREIGN KEY (club_name) REFERENCES Club(name)
        DEFERRABLE INITIALLY DEFERRED
);

CREATE TABLE Stakeholder (              -- weak entity type
    club_name   VARCHAR(50),
    name        VARCHAR(50),
    age         INTEGER      NOT NULL CHECK (age >= 0),
    percentage  NUMERIC(5,2) NOT NULL CHECK (percentage > 0 AND percentage <= 100),
    PRIMARY KEY (club_name, name),
    FOREIGN KEY (club_name) REFERENCES Club(name) ON DELETE CASCADE
);

ALTER TABLE Club ADD CONSTRAINT Captain_fk
    FOREIGN KEY (captain_pid, name) REFERENCES Player(pid, club_name)
    DEFERRABLE INITIALLY DEFERRED;

BEGIN;   -- a club and its captain arrive together
INSERT INTO Club   VALUES ('Lion FC', 'Singapore', 5000000, 7);
INSERT INTO Player VALUES (7, '1998-03-15', 'Forward', 80000, 'Lion FC');
COMMIT;
